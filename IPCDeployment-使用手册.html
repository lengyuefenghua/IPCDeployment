IPCDeployment-使用手册

本手册面向现场操作人员，只说明标准配置包的使用方法：如何选择配置、校验、开始部署、观察进度、停止任务、判断结果和查看日志。 不展开 XML 编写细节，也不涉及模切、下料、卷绕等独立配置包。

01

使用前须知

1.1 本手册的适用范围

本手册只适用于标准配置包：程序目录 config/ 下随包提供 config.xml，启动后默认加载。

  • 标准配置是通用基线，不绑定具体工位。
  • 模切、下料、卷绕等独立配置包不在本手册范围内；如果现场另外提供了这些配置，请以随附说明为准。
  • 界面文字、任务数量以实际运行版本为准；本手册用任务名和区域名描述，不依赖截图。

1.2 系统要求

  • Windows 10 或 Windows 11，64 位系统。
  • .NET Framework 4.7.2 或更高版本。
  • 目标机需要能够解压安装包、写入程序目录和系统目录。

1.3 权限与运行位置

必须以管理员身份运行。程序启动时会触发 Windows UAC；如果取消，程序可以打开，但无法执行部署。
  • 把发布包解压到可写目录，例如 D:\IPCDeployment。
  • 不要直接从只读目录、网络只读共享或压缩包预览窗口里运行。
  • 程序运行期间不要移动或删除程序目录。

1.4 执行会修改本机，且没有自动回滚

部署会安装软件、写注册表、调整电源和系统策略，可能还会安装数据库。程序不提供自动回滚、系统还原或自动重启。执行前请确认：

  • 这是正确的目标机，不是办公机或临时测试机。
  • 任务摘要里的分组、任务和步骤符合预期。
  • 机器上如果有需要保留的数据，已经完成备份。

1.5 先校验，再执行

每次执行前都先点“校验配置”，确认没有错误，再点“开始部署”。不要跳过校验直接执行。

2.2 左侧导航

  • 任务总览：查看配置摘要、统计、配置文件选择和任务概况。
  • 各分组：按分组查看任务和步骤；执行时这里会显示实时进度。
  • 部署完成：执行结束后查看成功、警告、失败、未执行和禁用统计；未执行过时点它会回到总览。

每个导航项左侧有状态符号，右侧显示进度。常见符号：

○ 等待/未开始　● 运行中　✓ 成功　! 警告　× 失败　– 未执行/已禁用/已满足

2.3 任务总览页

  • 顶部显示配置摘要和模式提示：执行模式会提示“开始前会显示任务摘要并再次确认；无自动回滚”。
  • 三张统计卡片：分组数、任务数、步骤数。禁用任务仍计入“任务”总数，但不计入执行进度。
  • “配置文件”卡片：配置方案下拉、编辑配置、校验配置、开始部署。
  • “校验问题”卡片：有错误或警告时出现，显示具体原因。
  • “任务概况”卡片：按分组列出任务和步骤数量，点分组可进入分组页。

2.4 分组页

  • 顶部显示分组名称、进度和状态；执行中会出现“停止部署”按钮。
  • 左侧“任务列表”：每个任务的进度和状态；已禁用任务显示“已禁用”。
  • 右侧“选中任务”：显示该任务的步骤、步骤类型、状态、耗时和“需重启”提示。
  • 底部日志区显示当前选中任务的日志。

2.5 部署完成页

  • 六张统计卡片：总任务、成功任务、警告任务、失败任务、未执行任务、禁用任务。
  • 左侧“分组结果”：按分组查看整体状态。
  • 右侧“任务结果”：查看每个任务的步骤、状态、原因和耗时。

2.6 底部日志与状态栏

  • “运行日志”区域在总览页和完成页显示全局日志；在分组页显示当前任务日志。
  • 日志自动滚动到最新一行；界面只保留最近一段日志，完整记录在日志文件里。
  • 右下角“打开执行日志”在日志文件存在时可用；“退出”关闭程序。
  • 状态栏左侧显示当前状态或日志路径，右侧是操作按钮。

2.7 按钮什么时候可用

按钮可用条件说明
编辑配置未在执行、未打开编辑器打开配置编辑器；编辑器打开期间不能开始部署。
校验配置未在执行重新读取当前配置并做预检。
开始部署执行模式、无错误、至少一个启用任务、未打开编辑器点击后还会弹出二次确认框。
停止部署正在执行只结束当前步骤和当前任务，不是整体取消队列。
打开执行日志日志文件存在用系统默认程序打开日志。
03

标准操作流程

第一次在目标机上使用时，按下面的顺序操作。每一步都确认“看到了什么”，再进入下一步。

  1. 解压发布包

    把 IPCDeployment-1.0.0-win-x64.zip 解压到可写目录。确认目录里有 IPCDeployment.exe、config\、data\、XML配置说明.md，以及发布时生成的 IPCDeployment-使用手册.pdf。

  2. 双击启动并确认 UAC

    双击 IPCDeployment.exe，在 Windows UAC 提示中点“是”。如果点“否”，程序仍能打开，但部署会因缺少管理员权限被预检拦住。

  3. 确认配置方案

    “任务总览” → “配置文件” → 下拉框，选择 标准配置（config.xml）。标准包通常只有这一项；如果下拉里还有其他配置，先确认现场要求再选。

  4. 点击“校验配置”

    程序会重新读取 XML、检查结构、检查管理员权限、检查源文件和运行条件。校验完成后，查看“校验问题”卡片和任务概况。

  5. 阅读预检结果和任务摘要

    没有“错误”才继续；“警告”可以先确认原因。重点看分组数、任务数、步骤数，以及哪些任务显示“已禁用”。

  6. 点击“开始部署”并二次确认

    确认框会列出配置名、分组数、启用任务数、禁用任务数和步骤数，并提示“没有自动回滚”。确认无误后点“确认执行”；不确定就点“取消”。

  7. 观察执行进度

    界面会自动跳到当前分组。看左侧任务列表和右侧步骤列表：当前任务显示“运行中”，步骤显示“成功 / 警告 / 失败 / 已满足 / 未执行”，右侧显示耗时。

  8. 查看执行结果

    结束后自动进入“部署完成”。先看六张统计卡片，再点左侧分组、右侧任务，定位失败或警告步骤及原因。

  9. 按提示重启

    步骤或任务显示“需重启”时，按现场要求重启。重启后再打开程序，重新校验并检查未完成的任务。

只做一次的动作：确认配置、校验、二次确认都不能省。校验通过不代表部署一定成功，它只说明配置和当前运行条件没有发现明显问题。
04

页面与控件详解

4.1 “校验配置”检查什么

  • XML 结构、元素和属性是否合法，文件路径是否越界。
  • 安装包、复制源文件和命令文件是否存在。
  • 是否以管理员身份运行。
  • 日志目录是否可写。
  • 安装包哈希（配置里写了哈希时）。
  • 网卡、服务、自启目标等运行期条件；这些通常以警告提示，最终以执行结果为准。
  • 禁用任务不参与运行期预检；它们仍会做结构校验。

4.2 错误与警告的区别

类型界面显示能否开始怎么处理
错误“错误 · …”不能按提示修正配置、文件路径或权限，再校验。
警告“警告 · …”可以确认原因；常见于服务尚未创建、自启目标稍后才安装等。
通过“配置校验通过。”可以仍要在二次确认框里核对摘要。

4.3 分组页的状态

符号文字含义
○等待还没开始。
●运行中 / 进行中当前任务或步骤正在执行。
✓成功所有步骤完成。
!警告步骤执行完成，但有需要关注的信息；后续步骤继续，任务最终以“警告”结束。
×失败有步骤失败，任务提前结束。
–已满足目标状态已经存在，没有重复执行。
–未执行前面步骤失败或任务被停止，这一步没有跑。
–已禁用配置里 enabled="false"，任务不执行。
■已取消用户停止或关闭程序导致的结束。

“警告”表示步骤已经执行完，但返回了配置允许的警告退出码，或者有需要现场确认的信息。它不会结束任务，后续步骤继续；任务最终计为“警告”，不会计为成功。警告详情写在日志的 WARN 行里。

4.4 步骤类型标识

步骤名称下方会显示类型：安装 复制 注册表 服务 网络 电源 自启 延时，命令类步骤显示 EXE、CMD 或 PowerShell。

类型只帮助识别步骤做什么，不影响操作；一线人员主要看状态、耗时和“需重启”。

4.5 结果页的统计

卡片含义
总任务配置里的全部任务数，包含禁用任务。
成功任务所有步骤完成的任务。
警告任务有步骤返回警告、但任务继续执行到结束的任务；计入“已结束”，不计入成功。
失败任务有步骤失败、提前结束的任务。
未执行任务因停止或取消而没有开始的任务。
禁用任务配置里标记为禁用的任务，不执行、不计进度。

4.6 日志显示规则

  • 总览页和部署完成页：显示全局日志。
  • 分组页：显示当前选中任务的日志；切换任务会切换日志内容。
  • 日志行带时间、级别和步骤标识；敏感字段（如 password、token）会被替换为 ***。
05

标准配置包含什么

标准配置分为“软件安装”和“系统优化”两个分组，另有一个默认禁用的数据库任务。实际任务名称和数量以界面为准。

5.1 软件安装

任务做什么现场注意
ImageDataViewer静默安装 ImageDataViewer，安装包已包含 ImageViewer 看图组件，并创建公共桌面快捷方式。默认安装目录已有看图组件时跳过；旧版本会自动升级。
日志分析工具静默安装 Jinovision 日志分析工具，并创建公共桌面快捷方式。安装到 C:\Program Files\JinovisionLogAnalyzer；已安装时跳过。
JinoMonitor静默安装 JinoMonitor，并创建公共桌面快捷方式。安装到 C:\Program Files\JinoMonitor；不设置开机自启；已安装时跳过。
ApowerREC解压到 C:\Program Files，创建公共桌面快捷方式。不设置开机自启。
Snipaste解压到 C:\Program Files，创建公共桌面快捷方式。不设置开机自启。
MSI Afterburner解压 MSIAfterburner-portable.zip 到 C:\Program Files (x86)\MSI Afterburner，创建公共桌面快捷方式，并创建登录时运行的计划任务。不包含显卡锁频 Profile；需要锁频时另行配置。
Wireshark先安装 Npcap 抓包驱动（已安装则跳过），再静默安装 Wireshark。Npcap 使用自动向导；被额外对话框拦截时步骤显示“警告”，按日志提示手动安装后重跑。
Process Explorer解压到 C:\Program Files，创建公共桌面快捷方式。首次启动会弹许可协议，属正常现象。
Everything静默安装 Everything。使用 x86 安装包；按默认目录判断是否已安装。

5.2 系统优化

任务做什么现场注意
高性能与大小核切换高性能电源计划，设置大小核异类调度策略。目标机需要暴露对应的异类电源设置；不支持时会失败并提示。
关闭 Windows Defender通过本地组策略和 Set-MpPreference 关闭实时保护。开启篡改保护或安装火绒、360 等第三方杀毒软件时可能被拦截。

5.3 数据库任务（默认禁用）

标准配置包含一个 MySQL 任务，默认不执行，界面显示“已禁用”。启用方法和行为见下一节。

如果当前配置版本里看不到数据库任务，说明该版本尚未包含它，不影响其他任务；不要为了“补任务”手工改配置，先联系配置维护人员。

5.4 标准配置不包含的内容

  • ImageDataViewer 的规则包导入。
  • HeidiSQL 数据库客户端。
  • JinoVision 共享库和 MySqlConnector.dll 复制。
  • 业务数据库（如 inovance、bmian）的创建。
06

禁用任务与 MySQL

6.1 “已禁用”在界面上的表现

  • 总览页的任务概况和分组页的任务列表显示“已禁用”。
  • 该任务的步骤显示“已禁用”，不会出现“运行中”。
  • 不执行、不产生执行步骤结果、不计入执行进度。
  • 确认框会单独提示“另 N 个任务已禁用，不执行”。
  • 结果页把它计入“禁用任务”卡片，但不计入成功或失败。

6.2 启用数据库任务

方法一：用配置编辑器

  1. 打开编辑器

    总览页点“编辑配置”。编辑器会以非模态窗口打开。

  2. 选中数据库任务

    左侧结构树展开“数据库”分组，点“MySQL 数据库”任务。

  3. 勾选“启用任务”

    右侧字段区找到“启用任务”，勾选。

  4. 保存

    点“保存”或按 Ctrl + S。保存后主界面会自动重新加载配置。

  5. 重新校验

    回到主界面点“校验配置”，确认没有错误，再开始部署。

方法二：直接改 XML

用文本编辑器打开 config/config.xml，找到数据库任务，把：

<Task key="..." name="..." enabled="false">

改成删除 enabled="false"，或改为 enabled="true"。保存后回到程序点“校验配置”。

改 XML 前先备份原文件。不要在程序执行期间修改配置；改完必须重新校验。

6.3 启用后会发生什么

场景行为
目标机没有 MySQL用默认安装位置安装 MySQL 8.4.7，初始化默认数据目录并启动服务。
目标机已有 MySQL 服务或默认数据目录检测到已存在后整组跳过：不卸载、不删除目录、不清空数据、不重新初始化。
安装完成注册并启动 MySQL84 服务；设置 root/root、创建 root@'%'、开放防火墙 3306。
业务数据库标准配置不创建 inovance、bmian 等业务库；由现场或后续配置处理。

默认位置

  • 程序目录：C:\Program Files\MySQL\MySQL Server 8.4
  • 数据目录：C:\ProgramData\MySQL\MySQL Server 8.4\Data
  • 服务名：MySQL84；端口：3306
安全提醒：启用数据库任务后，默认账号是 root/root，并且开放局域网 3306。部署完成后必须立即修改 root 密码，并确认防火墙只对需要的网段开放。不要把 root/root 留在生产机上。
已有数据的机器：程序不会主动删除 MySQL 数据，但数据库任务启用后仍会安装或配置服务。执行前先备份数据库，并在任务摘要里确认“MySQL 数据库”确实是需要的。

6.4 判断数据库任务是否真的执行了

  • 分组页里“MySQL 数据库”任务的状态：成功、失败或已满足。
  • 步骤列表里“安装/配置”步骤的状态和耗时。
  • 日志里搜索 MySQL，确认是“已存在，跳过”还是“安装/配置完成”。
  • 结束后打开“部署完成”，查看该任务是否有失败步骤或“需重启”。
07

停止、关闭与异常处理

7.1 点击“停止部署”

执行中分组页顶部会出现“停止部署”。点击后弹出确认框，提示：

“停止当前步骤并结束当前任务？剩余步骤将标记为未执行；已完成的更改不会自动回滚，可能留下部分更改。”
  • 点“停止部署”：结束当前步骤和当前任务，剩余步骤标记“未执行”。
  • 点“继续运行”：回到执行状态。
  • 停止不是“撤销”。已经安装的软件、写过的注册表、改过的系统设置都会保留。

7.2 执行中关闭窗口

执行中关闭主窗口会弹出“部署正在运行”提示：关闭窗口会停止当前步骤并结束当前任务，剩余步骤标记为未执行，可能留下部分更改。

  • 点“停止并退出”：停止并关闭程序。
  • 点“继续运行”：窗口不关闭，部署继续。

7.3 断电、强杀或系统崩溃

程序没有断点续跑。重新开机后：

  1. 先看日志

    打开 logs\deploy-*.log，确认最后执行到哪个任务、哪个步骤。

  2. 检查现场

    确认软件是否已安装、服务是否已创建、数据库是否有数据。

  3. 重新校验

    打开程序，选择配置，点“校验配置”。

  4. 再决定是否重跑

    已完成的安装步骤通常会显示“已满足”并跳过；数据库任务检测到已有实例也会跳过。仍要先确认任务摘要。

7.4 任务失败后会发生什么

  • 当前任务立即结束，剩余步骤标记“未执行”。
  • 程序继续执行下一个任务，后面的分组不受影响。
  • 没有“整体部署失败”状态，也没有自动回滚。
  • 失败原因显示在步骤详情和日志里；修好原因后可以重新校验并重跑。
08

结果判定与报告解读

8.1 状态含义

状态含义你需要做什么
成功步骤或任务正常完成。继续看下一项。
警告步骤完成但返回了配置允许的警告退出码；任务继续，最终以“警告”结束。看日志里的 WARN 行，按提示确认或补做操作。
失败步骤返回失败，或校验/运行条件不满足。看失败原因和日志，修正后重跑。
已满足目标已经存在，没有重复执行。通常不需要处理；确认是否符合预期。
未执行前序步骤失败、任务被停止或取消。确认是否需要重跑。
已禁用配置里标记为禁用。需要时按第 6 节启用。
需重启安装程序返回重启相关退出码，或步骤标记需要重启。按现场要求重启，再检查。

8.2 退出码

  • 0：通常表示成功。
  • 3010、1641：通常表示成功但需要重启；界面会显示“需重启”。
  • warnExitCodes 中列出的退出码：记为“警告”，不按失败处理；后续步骤继续。例如 Npcap 安装失败返回 201 时，任务继续，日志提示手动安装。
  • 其他退出码：按失败处理，除非配置里明确把它列为可接受。

8.3 报告怎么看

  1. 先看统计卡片

    失败任务、未执行任务是否为零；警告任务是否需要处理；禁用任务是否符合预期。

  2. 再看分组结果

    找到带“×”或“!”的分组。

  3. 展开任务结果

    看哪个步骤失败或警告、原因和耗时；需要重启的步骤会有标记。

  4. 对照日志

    日志里有更完整的命令输出和错误信息。

8.4 什么时候可以重跑

  • 失败原因已经排除，例如补齐文件、关闭杀毒软件、修正配置。
  • 目标机状态已经确认，不会因为重复安装造成数据丢失。
  • 重新执行前再次“校验配置”，并核对任务摘要。
09

日志与反馈

9.1 日志位置

  • 默认：程序目录 logs\deploy-时间戳.log。
  • 程序目录不可写时：回退到 %TEMP%\IPCDeployment\logs。
  • 状态栏或“部署完成”页会显示本次日志路径。
  • 点“打开执行日志”用系统默认程序打开；日志文件不存在时按钮不可用。

9.2 日志里能看什么

  • 配置路径和模式（execute / preview）。
  • 校验错误、警告和预检结果。
  • 每个步骤的开始、结束、退出码和输出。
  • 运行时警告：以 WARN 开头的行，包含警告原因和现场需要补做的操作。
  • 任务失败原因、未执行步骤和重启提示。
  • 敏感字段会被脱敏为 ***。

9.3 反馈问题时附上什么

  • 日志文件：logs\deploy-*.log。
  • 出问题的配置文件名和任务名。
  • 现象：哪一步失败、界面提示什么、是否重启过。
  • 目标机系统版本、是否管理员运行、是否安装第三方杀毒软件。
不要把整个程序目录打包发出去；只需要日志、配置文件和现象说明。配置里如果写了密码等敏感信息，发送前先确认。
10

常见问题

UAC 点了“否”，还能部署吗？

不能。预检会提示未以管理员身份运行。关闭程序，右键 IPCDeployment.exe 选择“以管理员身份运行”。

“开始部署”是灰的

常见原因：当前是 preview 模式、校验有错误、所有任务都被禁用、配置编辑器还开着、或者正在执行。先看“校验问题”和状态栏提示。

校验提示找不到文件

确认发布包解压完整，data\software、data\files 下的文件没有被杀毒软件隔离，也没有手工移动过。

任务显示“已禁用”，是不是坏了？

不是。配置里写了 enabled="false"。它不执行、不计进度。需要时按第 6 节启用。

关闭 Defender 失败

先关闭 Windows 安全中心的“篡改保护”；如果安装了火绒、360 等第三方杀毒软件，先退出或卸载，再重试。策略被拦截时任务会失败并提示。

Wireshark 的 Npcap 步骤显示“警告”

Npcap 免费版不支持全静默安装，程序会自动操作安装向导。如果被额外对话框拦截或超时，该步骤记为“警告”，Wireshark 仍会继续安装；日志会提示手动运行 data\software\npcap-1.88.exe，按“I Agree → Install → Next → Finish”完成后，重新运行本软件即可。Wireshark 本身安装时间也较长，等待步骤结束即可。

Process Explorer 首次启动弹协议

正常现象，接受许可后即可使用。

MSI Afterburner 解压后没有锁频

标准配置只解压便携包并创建登录自启计划任务，不包含显卡锁频 Profile。需要锁频时由后续配置或人工设置。

数据库任务启用了，但提示已满足

目标机已有 MySQL 服务或默认数据目录，程序按“存在就跳过”处理，不会删除或覆盖现有数据。确认现场是否本来就有数据库。

MySQL 连不上

确认 MySQL84 服务正在运行、防火墙 3306 已放行、使用 root/root 和 root@'%'。如果密码已被修改，以现场实际密码为准。

日志打不开

日志文件可能已被移动或删除。去 logs 或 %TEMP%\IPCDeployment\logs 找最新的 deploy-*.log。

执行到一半停电了

按第 7.3 节处理：先看日志和现场状态，再重新校验、确认任务摘要后重跑。程序没有断点续跑，也没有自动回滚。

11

安全红线

以下操作不要做：
  • 不要在部署运行中强杀进程、拔电或强制重启，除非现场已经无法继续。
  • 不要在未核对配置和任务摘要时点“确认执行”。
  • 不要在需要保留数据的机器上盲目启用数据库任务；先备份。
  • 不要从只读目录、压缩包预览窗口或网络只读共享直接运行。
  • 不要随意修改已经验收的配置文件；确需修改时先备份，再校验。
  • 不要把 root/root 和开放 3306 的状态留在生产机上。
  • 不要用“重跑”代替排查；重复执行可能重复安装或重复修改系统设置。
推荐做法：每次执行前备份配置和日志；执行后核对统计卡片、失败步骤和“需重启”；把日志和现象一起反馈。

13.1 配置编辑器快速上手（进阶）

配置编辑器用于查看和修改 XML，不是日常部署的必经步骤。打开后主界面会暂时不能开始部署，保存后自动重新加载。

  • 顶部：配置下拉、新建、保存、另存为、当前文件路径、模式标记、问题数量。
  • 左侧：搜索框和结构树；右键可新增分组/任务/步骤、上移、下移、删除。
  • 右侧：选中节点的字段区；字段下方会显示校验错误。
  • 底部：保存状态、快捷键提示；有错误时出现“问题”面板，点条目可定位节点。
