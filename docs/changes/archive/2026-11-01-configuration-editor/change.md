# 配置编辑器 ConfigurationEditor

## 需求卡
目标：让运维在程序里可视化编辑配置文件，保存后即可直接部署，不必手写 XML。

验收标准：
1. 正常：主窗口打开编辑器 → 新增分组、任务、步骤（键与 id 自动生成、只读展示）→ 改分组名 → 保存 → 主界面立即显示新名称。
2. 往返保真：任务下新增九类步骤各一个并填必填项，再把分组上移后保存；重开文件，字段值、节点顺序和原有注释都不变。
3. 失败：源路径填 `C:\x.exe` 后保存 → 不写文件、编辑内容保留、列出一条字段级错误且可定位到该步骤。
4. 失败：打开 `schemaVersion` 非 2.0 的文件 → 不进入编辑，弹窗显示加载器的行列错误。
5. 失败：编辑器打开后文件被外部改动，点保存 → 提示「文件已被外部修改」，可选覆盖或取消。
6. 失败：保存时目标文件被占用 → 不留半写文件，提示写入失败原因。
7. 边界：有未保存修改时关闭窗口 → 保存 / 不保存 / 取消 三选。

非目标：模板库与向导、SHA-256 计算、XML 文本视图、改步骤类型、并发编辑加锁、保存 `execute` 模式时的二次确认（与手写 XML 一致）。

## 协作卡（类图形）
边界：单进程 WPF 桌面程序；编辑器与部署页同进程、不同窗口，共享 Core 的配置加载与运行日志。
图例：[增]=新增　[改]=修改　[有]=既有复用（不动）　──▶=调用方向

[改] 主窗口（MainWindow） ──打开──▶ [增] 配置编辑器窗口（ConfigurationEditorWindow）
[增] 配置编辑器窗口 ──结构树/属性表单──▶ [增] 编辑器文档（ConfigurationDocument） ──▶ [增] 字段表（ConfigFieldSchema）
[增] 编辑器文档 ──校验（写同目录临时文件后调用）──▶ [有] 配置加载器（ConfigLoader）
[增] 编辑器文档 ──备份+原子替换──▶ 文件系统：config.xml / <文件名>.bak
[改] 主窗口 ──保存后重载──▶ [有] 部署视图模型（DeploymentViewModel） ──▶ [有] 部署外壳（DeploymentShell）
[改] 主窗口 ──记一行──▶ [有] 运行日志（DeploymentLog）

共享接口：编辑器文档（ConfigurationDocument）是编辑器的唯一公共入口——打开（路径 → 文档或加载错误）、保存（路径、是否覆盖外部修改 → 保存结果或字段级错误，内部先序列化到同目录临时文件再交给加载器校验）。字段表（ConfigFieldSchema）是九类步骤字段的唯一定义处。
改动边界：新增＝ConfigFieldSchema、ConfigurationDocument、编辑器视图模型与字段视图模型、ConfigurationEditorWindow；修改＝MainWindow（工具栏按钮、打开与重载、日志转发）、DeploymentViewModel（编辑器打开标记并入可开始判断）、DeploymentShell（一行日志入口）；复用不动＝ConfigLoader、PathPolicy、PreflightChecker、DeploymentRunner 与全部执行器。
不变量：保存结果必须仍能通过加载器；注释、属性顺序、节点顺序保留；Core 不引用 System.Windows；编辑器从不执行步骤、不读写 data/。
禁止形状：在 UI 里解析或拼 XML；为通过校验而放宽加载器规则；编辑器直连 runner 或执行器；第二套字段定义。
偏离定义：需要加载器放宽或新增 schema 版本 → 视为新变更。

## 流程契约
触发：主窗口点「编辑配置」（唯一入口）。
入口参数：当前配置文件路径（单入口）。
主链：
主窗口「编辑配置」 → 打开编辑器窗口（当前配置路径；文件不存在则最小骨架） → 读取并校验源文件（加载器；不通过则不进入编辑） → 结构树选节点、属性表单改字段（就地改文档，标未保存） → 保存（检测外部修改 → 序列化到同目录临时文件 → 加载器校验 → 写备份副本 → 原子替换） → 主窗口重载 → 状态行报已保存路径与时间（运行日志记一行）
返回：成功 = 已保存并重载；失败 = 枚举（校验未通过、外部已修改、文件占用或 IO 失败、打开即不合法），统一在编辑器内呈现。
异常线：
- 打开时加载器报错 → 不进入编辑，错误对话框列出行列，运行日志 WARN
- 保存校验失败 → 不写文件、保留编辑内容，InfoBar 列出可点击定位到节点的错误，运行日志 WARN
- 保存前发现文件被外部修改 → 弹「覆盖 / 取消」，默认取消，运行日志 WARN
- 备份或替换 IO 失败 → 保留原文件与备份副本，提示失败原因，运行日志 ERROR
- 关闭、新建、打开其他文件遇未保存修改 → 保存 / 不保存 / 取消，取消则不动作
- 编辑器窗口打开期间主窗口「开始部署」置灰，不进入预检

## UI 草图
独立窗口，约 1100×720，浅色标题栏与浅色内容区，延续现有 Fluent 浅色方向。

```
┌ ui:TitleBar「配置编辑器」                                    ─  □  ✕ ┐
├ 工具栏 ui:Card ─────────────────────────────────────────────────────┤
│ [新建] [打开…] [保存] [另存为…]      C:\...\config.xml   •未保存     │
├ 结构树 260px ──────┬ 属性面板（自适应宽，可滚动）───────────────────┤
│ ui:TreeView        │ ui:Card 标题行：<名称>   ui:Badge 类型          │
│  ▸ 配置            │ ── 公共字段 ─────────────────────────────       │
│  ▾ 分组 软件安装    │ 键（ui:TextBox） 名称（ui:TextBox）            │
│    ▾ 任务 MySQL    │ ── 类型字段（随选中类型切换）───────────────    │
│       · Delay 等待 │ 源路径（ui:TextBox + 说明 ui:TextBlock）        │
│       · Command 脚本│ 超时（ui:NumberBox） 退出码（ui:TextBox）      │
│    · 任务 示例命令  │ 内嵌 Code（多行 ui:TextBox）                   │
│  ▸ 分组 文件复制    │                                               │
├────────────────────┴───────────────────────────────────────────────┤
│ 操作条：[新增分组][新增任务][新增步骤 ▾][删除][↑][↓]                 │
│ ui:InfoBar 校验结果（默认收起；失败展开，每条可点跳转节点）           │
└────────────────────────────────────────────────────────────────────┘
```

交互要点：
- 选「配置」节点改 `mode`（ui:ComboBox）、Meta、日志目录；选分组只能加任务；选任务加步骤并选九类之一；选步骤不能再加子项。
- 字段改动立即标「未保存」，输入过程中不校验；只有点保存才跑配置校验。
- 保存顺序：外部修改检测 → 临时文件 → 校验 → 备份副本 → 原子替换 → 通知主窗口重载。
- 关闭、新建、打开其他文件遇未保存修改 → 保存 / 不保存 / 取消。
- 打开失败用错误对话框展示行列；保存失败用 InfoBar 展示可定位错误。
- 删除分组或任务需二次确认（会连带删除子项）；上下移动按钮只在该层内生效。
- 编辑器窗口打开期间主窗口「开始部署」置灰。

## 影响
- 能力：新增 `configuration-editor`（`specs/configuration-editor/spec.md`）。
- Data：none，不迁移格式；保存沿用现有 schemaVersion 2.0 结构与九类步骤。
- Risks：往返保真依赖搬移节点时把整段注释与缩进一起搬，漏搬会静默丢注释；校验走临时文件，临时文件写不出会被当作校验失败；外部修改检测只比时间与长度，同一秒内的外部改写可能漏检；打开时加载器会检查 data/ 下的安装包与命令文件，载荷未就位时该配置无法在编辑器中打开。
