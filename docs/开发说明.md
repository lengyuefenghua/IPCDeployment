# 开发与打包

本文件面向仓库开发者，不随发布包分发；用户使用手册见根目录 `IPCDeployment-使用手册.html`（发布包内为 `IPCDeployment-使用手册.pdf`），配置编写参考见 `XML配置说明.md`。

## 项目结构

- `src/IPCDeployment`：WPF-UI 4.3.0 桌面程序；`Core/` 为不依赖 WPF 的逻辑。
- `tests/IPCDeployment.Tests`：NUnit 测试，Windows net472。
- `config/`：标准配置 `config.xml`（可切换的直属 XML），`config.sample.xml` 仅作示例。
- `config-lithium/`：模切/下料/卷绕三份锂电专用配置，不随标准包发布。
- `data/`：安装包、文件、命令和规则包。
- `scripts/`：构建、调试、打包脚本。
- `build/debug`：开发运行目录，不生成 ZIP（只含标准配置）。
- `dist/IPCDeployment-<版本>-win-x64` 与同名 ZIP：标准发布目录和压缩包；`dist/IPCDeployment-<版本>-lithium-config` 与同名 ZIP：锂电配置包（只含三份 XML）；`dist/` 已 gitignore。

## 常用命令

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-debug.ps1
dotnet test IPCDeployment.sln -c Debug
dotnet build IPCDeployment.sln -c Release
powershell -ExecutionPolicy Bypass -File scripts/package-portable.ps1
```

- 日常开发用 Debug 构建和测试；Release 只在打包前使用。
- 聚焦测试示例：`dotnet test IPCDeployment.sln -c Debug --filter "FullyQualifiedName~ConfigLoaderTests"`。
- `scripts/build-debug.ps1` 复制程序、`config/`、`data/`、`IPCDeployment-使用手册.pdf`、`XML配置说明.md` 到 `build/debug`。
- `scripts/package-portable.ps1` 复制同样的内容到 `dist/IPCDeployment-<版本>-win-x64` 并生成同名 ZIP；同时把 `config-lithium/` 的三份锂电配置打到 `dist/IPCDeployment-<版本>-lithium-config.zip`（ZIP 内为 `config/*.xml`，复制进标准包的 `config/` 后可选）。
- 发布版本号唯一源是当前 HEAD 的 git tag；构建时 csproj 读取同一 tag（无 tag 时回退 `<Version>`），About 和标题栏显示同一份 ProductVersion；打包会校验 exe ProductVersion 与 tag 一致。发布顺序：提交 → 人工验收 → 打 tag → 在该 tag 上重新构建并打包。
- 发布前先运行 `scripts/check-source-packages.ps1`，检查 `ImageDataViewer`、`JinovisionLogAnalyzer`、`JinoMonitor` 的源仓库 `dist` 是否比 `data/software` 新；有更新时执行 `-Apply`，构建、测试并提交后再打包。打包脚本会再次检查，配置落后时直接失败。
- 程序为 x64 目标，界面标题栏显示的版本号取自程序集产品版本。
- 测试使用临时目录和 fake process runner，不需要管理员权限，也不会修改本机。

## 验证边界

- 不启动 `IPCDeployment.exe`，不执行真实部署；构建、测试、打包和检查文件即可。
- 真实安装、注册表、网卡、电源和服务操作由用户在代表性测试机上执行。
- 界面验收由用户自行启动程序目视确认；不依赖截图或自动化界面操作。

## 配置契约

- 用户/AI 配置说明：`XML配置说明.md`。
- 实现契约：`docs/specs/deployment-config.md`。
- 配置加载、预检、执行器和测试位于 `src/IPCDeployment/Core` 与 `tests/IPCDeployment.Tests`。
